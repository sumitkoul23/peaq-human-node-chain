# Liquidity and listing plan

## Principle
Do not chase “every exchange” before the market exists. Build depth first, then breadth:
1. credible liquidity
2. transparent market data
3. verified contracts and audits
4. staged exchange applications

## Phase 1 — Native liquidity
- Seed the first PHN / PEAQ pool on a peaq-native DEX once a suitable venue is chosen
- Keep an explicit liquidity allocation wallet and publish its label
- Use a narrow launch range at first, then rebalance only under a written policy
- Track:
  - liquidity depth
  - 2% slippage size
  - volume
  - unique holders
  - daily active node operators

## Phase 2 — Market data readiness
- Publish:
  - website
  - whitepaper
  - tokenomics
  - explorer links
  - verified contracts
  - GitHub repository
  - circulating supply method
- Apply to token trackers only after PHN is actively tradable on a tracked exchange, because CoinGecko requires live trading on a tracked venue before a standard listing request.  

## Phase 3 — Exchange ladder
### Tier A: DEX and discovery
- peaq-native DEX
- CoinGecko / CoinMarketCap preparation
- token list submission
- dashboard and analytics

### Tier B: regional / emerging CEXs
- apply once there is real liquidity, community, and repeated daily volume
- target only exchanges that fit PHN’s geography, compliance posture, and chain support

### Tier C: major CEXs
- Kraken
- Coinbase
- Binance / Binance.US where eligible

These venues do not list by request alone. Kraken says it uses strict legal, compliance, engineering, and business standards; Coinbase prioritizes demand, traction, and expected liquidity; major venues require a formal application and review path.  

## Readiness gates before major exchange applications
- contract verification complete
- audit complete
- multisig/timelock active
- transparent tokenomics
- visible usage metrics from verified nodes
- healthy holder distribution
- real exchange volume
- no unresolved legal/compliance gaps
- market-making and treasury policy approved

## Liquidity budget sketch
| Bucket | Suggested use |
|---|---:|
| Launch liquidity | 3,000,000 PHN |
| Reserve liquidity | 4,000,000 PHN |
| Market-making / incentives | 2,000,000 PHN |
| Emergency buffer | 1,000,000 PHN |

This fits the existing 10,000,000 PHN liquidity allocation without inventing new supply.

## What success looks like
- tight spreads
- meaningful depth
- reliable price discovery
- active verified-node economy
- listings earned by traction rather than bought by noise
